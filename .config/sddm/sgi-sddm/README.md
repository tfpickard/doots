# SGI Indigo — SDDM theme

A Silicon Graphics styled greeter, matched to the desktop lock screen so the
machine looks the same before and after login.

![preview](preview.png)

## Provenance

This is a **re-skin, not a rewrite**. It is derived from
[JaKooLit/simple-sddm](https://github.com/JaKooLit/simple-sddm) (the Qt5
variant, which was itself derived from tokyo-night-sddm by rototrash), and is
GPL-3.0-or-later like its parent. Upstream `LICENSE`, `COPYING` and
`README.upstream.md` are kept in this directory.

What actually differs from upstream:

| | |
|---|---|
| `Main.qml`, `Components/` | **unmodified**; changes live in `patches/` and are applied at install time |
| `Assets/` | the five icons redrawn as pixel art, generated by a script |
| `theme.conf` | re-coloured to the SGI palette, form centred, chrome flattened |
| `Backgrounds/` | five stock images removed (2.3 MB); replaced with `sgi-indigo.png` |
| `metadata.desktop`, `README.md`, `preview.png` | this theme |

Keeping the QML itself untouched means upstream fixes can be pulled in by
copying the QML back over: re-run the install and the patches either apply or
tell you exactly which hunk moved.

**This is a Qt5 theme.** It needs `qml-module-qtquick-controls2`,
`qml-module-qtgraphicaleffects`, `qml-module-qtquick-layouts` and `libqt5svg5`
(all present on this machine), and it runs under `/usr/bin/sddm-greeter`, not
`sddm-greeter-qt6`.

## Palette

Sampled from `~/Pictures/Wallpaper/indigo.png`, which is 89% one flat colour:

| role | colour | |
|---|---|---|
| SGI field blue | `#29558e` | the background, and the raised button face |
| deep indigo | `#14294d` | `BackgroundColor`, and the sunken field faces |
| white | `#ffffff` | `MainColor` — text, including the login button |
| light blue | `#8fc0ff` | `AccentColor` — focus and hover |

The same values drive the lock screen (`.config/swaylock/config` and
`.config/swaylock-effects/config`), so the greeter and the lock match.

## The background

`Backgrounds/sgi-indigo.png` is generated, not hand-made:

```sh
~/.config/scripts/lock-background.py --size 2560x1600
cp ~/.cache/sgi-lock/2560x1600.png Backgrounds/sgi-indigo.png
```

That script lifts the white logo out of the wallpaper as an alpha mask and
re-composites it at the requested size, so it stays crisp instead of being
upscaled from the 1280x800 original.

It is rendered at 2560x1600 (16:10) and committed **into the theme** rather
than referenced from `~/.cache`, because **SDDM runs as the `sddm` user and
cannot read your home directory**. A background path under `/home/tom` silently
gives you a blank screen.

`ScaleImageCropped="true"` handles the aspect difference on a 16:9 panel; the
logo sits in the upper third, so cropping top and bottom doesn't clip it.

## Making it look like 1995

Sugar Candy is a 2018 theme: flat fields, a drop shadow behind the form,
rounded corners, smooth Material icons. `theme.conf` turns off what it can
(`RoundCorners=0`, `InterfaceShadowSize=0`, `InterfaceShadowOpacity=0`), and
the rest is done by `patches/` and by redrawn `Assets/`.

### The patch series

`patches/*.patch` are applied in filename order, `patch -p1` from the theme
root, by `make sddm`. They are the only thing that touches upstream QML.

| | |
|---|---|
| `01-motif-chrome.patch` | Motif bevels on the fields, checkbox and login button; fixes a font-family bug |
| `02-pixel-icon-grid.patch` | snaps icon sizes to the pixel grid the new Assets are drawn on |

**A Motif bevel takes three rectangles, not one.** A `Rectangle` has a single
`border.color`, and a bevel needs two: light top-left plus dark bottom-right
reads as raised, inverted reads as sunken. So each bevelled control is an
outer rectangle painting the bottom-right edge, a middle one inset 2px right
and bottom painting the top-left edge, and an inner one inset 2px all round
for the face. The face colour is exposed as a `faceColor` property so the
existing `states:` blocks can keep driving it.

**Do not reorder those `states:` blocks.** When several `when` clauses are true
at once QML applies the *first* match, so `enabled` has to stay last — put it
first and it masks `pressed`, `hovered` and `focused` and the button stops
reacting.

`01` also fixes a pre-existing upstream bug: several controls replace their
`contentItem` with a plain `Text`, which does **not** inherit the root font the
way a `Label` does. They set `font.pointSize` but never `font.family`, so they
silently ignored `config.Font` and rendered in the app default sans while
everything else used JetBrains Mono. The patch adds `font.family` at all seven
sites.

### The icons

`Assets/{User,Shutdown,Reboot,Suspend,Hibernate}.svgz` are generated by
[`~/.config/scripts/sddm-pixel-icons.py`](../../scripts/sddm-pixel-icons.py),
which draws each one as ASCII art on a 14×14 grid and emits one `<rect>` per
horizontal run. Edit the art in that script and re-run it; the originals are
in git history.

Three constraints worth knowing before touching them:

- **The filenames are a contract.** `Input.qml` and `SystemButtons.qml` build
  paths as `../Assets/<Name>.svgz`, so the names and the gzipped-SVG extension
  are fixed.
- **Colour comes from QML.** Both call sites set `icon.color`, which recolours
  the whole glyph, so the fill in the SVG is arbitrary.
- **The drawn size must be a whole multiple of 14, and at least 28.** This is
  what `02` is for. At a non-multiple the renderer lands cell boundaries on
  fractions of a pixel and antialiases the blocks straight back into the smooth
  glyphs they replaced. At exactly 14 it is crisp but pointless — one cell per
  screen pixel leaves nothing to see. Pixel art needs a cell to be a *visible
  block*, so the floor is two screen pixels per cell. Upstream asked for about
  12px; the patch asks for 28.

Drawing them at this size is unforgiving and two of the five fought back:

- A crescent drawn as an **outline** closes into a thick "C" and becomes
  indistinguishable from Reboot sitting next to it.
- A crescent drawn at **uniform thickness** reads as a bracket. It only says
  "moon" once the belly is fat and the tips flare back toward the bite.

Check them without the greeter, which is useful because the system buttons
don't render in `--test-mode` at all (see *Known upstream warnings*):

```sh
~/.config/scripts/sddm-pixel-icons.py /tmp/icons
cd /tmp/icons && for f in *.svgz; do gunzip -c "$f" > "${f%z}"; done
convert -background '#29558e' User.svg Shutdown.svg Reboot.svg \
        Suspend.svg Hibernate.svg \
        -resize 28x28 +append -filter point -resize 400% /tmp/strip.png
```

The gunzip step is not optional — ImageMagick will not read `.svgz`. And
`-filter point` matters: scale the preview with anything else and you are
judging the blur, not the art.

## Installing

SDDM only looks in `/usr/share/sddm/themes`, and it runs as the `sddm` user, so
the theme has to be reachable from outside `$HOME`:

```sh
make sddm
```

That copies the theme into place, applies `patches/` over it, installs the font
system-wide, and points `/etc/sddm.conf.d/theme.conf.user` at it.

**It copies rather than symlinks, and that is deliberate.** A symlink kept
edits live, which was nice, but you cannot patch through one: `patch` would
rewrite the tracked files in the repo and leave it permanently dirty. The cost
is that edits under `.config/sddm` are no longer live — re-run `make sddm` to
see them.

**`make sddm` also sweeps `/etc/sddm.conf.d`.** SDDM reads *every* file in that
directory whatever its extension, in sorted order, and the last `Current=`
wins — so a backup left next to the real config shadows it. That is not
hypothetical: `theme.conf.user.bak-simple-sddm` sorts after `theme.conf.user`
and silently held the greeter on the stock theme. Any other file setting
`Current=` is moved to `/etc/sddm.conf.d.backups`, outside the read path.

Preview it without logging out:

```sh
sddm-greeter --test-mode --theme /usr/share/sddm/themes/sgi-sddm
```

Config is read once per daemon start, so changes need `systemctl restart sddm`
— which kills the running session. No reboot required, but log out first.

## Fonts

`Font="JetBrainsMono Nerd Font"` has to be readable by the **`sddm` user**, not
just by you. Fonts under `~/.local/share/fonts` are not — that is where this
machine keeps them, so they are additionally installed to
`/usr/local/share/fonts` for the greeter. If the greeter falls back to a
default sans, that link is what broke.

## Rolling back

The previous setting is backed up in `/etc/sddm.conf.d.backups/` — `make sddm`
moves anything that also sets `Current=` there, so it no longer shadows the
real config:

```sh
sudo cp /etc/sddm.conf.d.backups/theme.conf.user.bak-simple-sddm \
        /etc/sddm.conf.d/theme.conf.user
```

If a theme fails to load, SDDM falls back to its own built-in greeter rather
than refusing to start, so a broken theme means an ugly login — not a locked-out
machine. You can also switch from a TTY (`Ctrl+Alt+F3`) if the greeter is
unusable.

## Known upstream warnings

`sddm-greeter --test-mode` prints these. All of them are **also produced by the
unmodified upstream theme**, with `patches/` unapplied — they are not
introduced by this re-skin:

```
Components/SystemButtons.qml:70:13: Unable to assign [undefined] to QQuickItem*
Components/SessionButton.qml:38:5:  Unable to assign ComboBox to Control
Main.qml:34/35: ReferenceError: Screen is not defined
```

The first one has a practical consequence: the Suspend/Hibernate/Reboot/
Shutdown buttons **do not appear in `--test-mode` at all**, so their icons
can't be checked through the greeter. Rasterize the SVGs directly instead —
see *The icons* above.

`module "QtQuick.VirtualKeyboard" is not installed` was also in that list; this
theme sets `ForceHideVirtualKeyboardButton="true"` since the module genuinely
isn't installed here, which stops the greeter offering a button that can't work.
